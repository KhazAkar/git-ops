# BL-2026-11-16-001 - watch_pipeline workflow

Backlog item (feature-sized, not scheduled).

## What

A second git-ops workflow: given a project and a ref (or a tag),
watch the GitLab pipeline until it completes, then report status,
jobs, and failure excerpts. The natural follow-on to a mint:
mint the tag, watch the tag pipeline, report green or red with
the failing job tail.

## Why

Today pipeline observation goes through the chat connector
(list_pipelines polling), which burns session context and
repeats the gate story. A resident workflow can poll with
backoff and return one summary.

## Rough shape (to be ADR'd when scheduled)

- Input: project_path, ref, timeout_seconds, poll interval.
- Reads only: existing GitLab plumbing plus a pipeline endpoint
  in `gitlab.py`.
- Output: status, web_url, failing job names and excerpted
  tails.
- Open questions: timeout policy (fail vs report still-running),
  maximum poll duration on the platform, excerpt size.

## Dependencies

- tag_minter shipped (it is; this can build on the same gitlab
  module).
- Pipeline endpoint response shape verified against real data.
